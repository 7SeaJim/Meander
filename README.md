# 扩散规则

规则与设计的出发点见 [规则书.md](规则书.md)（Ver.1.1）。`diffusion.ts` 是单人规则的引擎，`duel.ts` 是对战草案的引擎；
规则只写在这两个文件里，`web/` 是它们的网页界面。

```sh
npm run open    # 构建并打开沙盘 dist/index.html
npm run duel    # 构建并打开对战 dist/duel.html
npm run build   # 只构建
npm run demo    # 命令行跑 diffusion.ts 自带的 demo
npm run verify  # 随机检验规则书「待验证」清单(稳态 vs 锥面预测 / 策略无关性)
npm run sim     # 对战规则的随机/贪心对局:不变量与先后手胜率
```

需要 Node ≥ 22.13（用自带的类型擦除，无任何依赖）。`dist/` 下的两个页面都是自包含的单文件，
可直接双击打开或拷走。改了引擎或 `web/` 后重新 `npm run build`。

## 两套扩散规则（`diffusion.ts`，`rule` 参数）

共同：每格 0–9，每次由值最大的可扩散格扩散，同值平手按调度策略；没有可扩散格时结束。

- **Ver.2 邻域规则**（`"block"`，对战默认）：N = 周围 3×3 的 8 格之和。本格 a > N 时，逐个给出 1，
  按 上→右→下→左 轮流给四邻，直到 a ≤ N；只给比本格至少低 2 的邻格。周围无水时 2n 停在 n、
  2n+1 停在 n（7 → 中心 3、四邻各 1；9 → 中心 4、上 2、其余各 1）。「至少低 2」保证平方和严格递减、
  必然停机，否则一格宽的死胡同里 2、1 两格会无限来回。
- **Ver.1.1 成对规则**（`"pair"`，规则书原版）：主格与按 上→右→下→左 第一个差 > 1 的邻格对半分。

3000 个随机盘面（3×3–12×12，含墙）上 Ver.2 全部停机且守恒，单盘最多 18 步。同一格连倒三次 9，
Ver.1.1 摊成最高 2 的缓坡，Ver.2 能停在中心 8、上方 4。

## 沙盘（index.html）

- **扩散规则**：Ver.2 邻域（默认）/ Ver.1.1 成对，可随时切换。

- **画笔**：数字 0–9（键盘 `0`–`9`）、墙（`W`）、源（`S`）。数字和墙可拖动连画。
  「源」以当前数字把格子标记为注入点，再点一次取消标记。
- **演化**：单步（空格）、播放/暂停（回车）、沉降到底。最近一步的主格为实线框，
  客格为虚线框，箭头旁的数字是搬运量。
- **平手策略**：scan / fifo / lifo，对应引擎的 `Strategy`。
- **源与稳态**：「注入一次」把各源设回源值；「求稳态」调用 `steadyState()`。
  勾选「对比锥面预测」后，每格右下角显示 `conePrediction()` 的值，不符的格标红。

## 对战草案 4（duel.html）

规则书里没有这部分，规则以 `duel.ts` 顶部的注释为准。

- 两方各有一层水，每层都按 Ver.2 邻域规则各自扩散、互不阻挡；同一格可同时有两方的水。
- 每回合得到 `budget` 个泉，自由分配：每放 1 个泉，该格己方水量 +1（单格上限 9）。
  可全压一格，也可分到多格；不能放在墙或对方占领的格上。泉是一次性倒下的水，之后不再补。
- 确认后只有落子方那一层扩散到静止。
- 一轮（双方各一回合）结束时逐格结算：比较这一格 3×3 范围内（含本格）双方的水量总和，
  多的一方占有；相等则僵持，维持原主。
- 每轮交换先手（`alternate`，默认开）：橙青、青橙、橙青……
- 结算后占领过半者胜；否则打满回合数后比占领格数。
- 青方可选同屏玩家或电脑（`greedyTurn`：试每堆 9 / 3 / 1 三种拆法，每堆放到预演格数差最大的格）。

页面操作：点格子放 1 个泉，右键或「撤回一个」（`Z`）收回，回车确认。扩散速度分慢 / 中 / 快 / 瞬时，
扩散中可暂停（空格）、单步（`→`）、跳到结束。

历史草案：草案 1（水带符号、相遇抵消）在 `9485c52`；草案 2（永久泉、每回合固定个数）在 `f580952`；
草案 3（Ver.1.1 扩散、按倍数夺格）在 `8b7fb39`。

### 模拟结果（草案 4）

`node sim.mjs quick` 某一次运行的结果（先手胜 : 后手胜 : 平；乱放的机器人各 100 局，贪心各 10 局，
样本小，只看趋势）。「集中9 / 三堆3 / 九个1」指把 9 个泉按该拆法放到随机合法格。

| 对局（前者先手） | 9×9，交换先手（默认） | 9×9，不交换先手 | 13×13，12 轮 |
| --- | --- | --- | --- |
| 集中9 vs 集中9 | 60 : 40 : 0 | 50 : 49 : 1 | 51 : 46 : 3 |
| 九个1 vs 九个1 | 49 : 51 : 0 | 55 : 45 : 0 | 51 : 49 : 0 |
| 集中9 vs 九个1 | 0 : 100 : 0 | 0 : 100 : 0 | 0 : 100 : 0 |
| 九个1 vs 集中9 | 99 : 1 : 0 | 100 : 0 : 0 | 100 : 0 : 0 |
| 贪心 vs 贪心 | 7 : 3 : 0 | 0 : 10 : 0 | 5 : 5 : 0 |

- 平局几乎消失；易主 9×9 每局 4–15 格，13×13 贪心对贪心每局约 48 格。
- 不交换先手时后手大优（贪心 0 : 10），交换后大致平衡。
- 分散压倒集中：13×13 上贪心 38 个回合里 21 次把 9 个泉分到 9 格，单格最多叠 3 个。
  每回合平均只扩散约 1 步——单个 1 不会流动，而 3×3 结算让每个泉无论叠不叠都恰好影响 9 格的总和。

### 夺格规则能否并入原规则（草案 3 时期的实验记录，Ver.1.1 扩散）

9×9、每回合 9 泉、8 轮，贪心对贪心各 12 局（先手胜 : 后手胜 : 平）：

| 归属规则 | 新增概念 | 贪心 vs 贪心 | 易主 次/局 |
| --- | --- | --- | --- |
| 单层带符号、相遇抵消（草案 1 的盘面 + 自由分配） | 只有「水分正负」 | 0 : 0 : 12 | 5.2 |
| 两层，谁水多归谁，平手变无主 | 第二层 | 0 : 0 : 12 | 1.7 |
| 两层，谁水多归谁，平手归原主 | 第二层、原主保留 | 4 : 6 : 2 | 1.5 |
| 两层，1.5 倍，不足归原主（草案 3 默认） | 第二层、原主保留、倍数 | 1 : 8 : 3 | 3.1 |

没有「原主保留」的两种全部平局，分差恒为 0，且与棋盘大小无关：两种规则在 4×4、5×5、6×6、7×7、
9×9、11×11、13×13 上各 12 局全部平局；把每回合泉数加到 27 也一样。唯一例外是 3×3（棋盘格数等于
一回合的泉数）：单层版先手第 1 轮就过半获胜（12 : 0 : 0），两层版为 0 : 7 : 5。

原因是守恒加平坦，而不是棋盘大小：双方总水量相同，每层静止后相邻差 ≤ 1。单层版里抵消让盘面始终
稀疏，各种尺寸下水量 > 1 的格都是 0%，格数就等于水量。两层版在小棋盘上水很厚（4×4 时 100% 的格 > 1），
但两层同样平坦，逐格差只有 ±1；总差为 0，于是赢的格数恰好等于输的格数。

## 结构

- `build.mjs` 把擦除类型后的引擎与界面脚本拼进同一个 `<script type="module">`，
  所以 `web/app.js`、`web/duel.js` 直接使用引擎里的名字，不写 import。
