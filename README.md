# 扩散规则 Ver.1.1

规则与设计见 [规则书.md](规则书.md)。`diffusion.ts` 是单人规则的引擎，`duel.ts` 是对战草案的引擎；
规则只写在这两个文件里，`web/` 是它们的网页界面。

```sh
npm run open    # 构建并打开沙盘 dist/index.html
npm run duel    # 构建并打开对战 dist/duel.html
npm run build   # 只构建
npm run demo    # 命令行跑 diffusion.ts 自带的 demo
npm run verify  # 随机检验规则书「待验证」清单(稳态 vs 锥面预测 / 策略无关性)
npm run sim     # 对战规则的随机/贪心对局:不变量与先后手胜率
```

需要 Node ≥ 22.13（用自带的类型擦除，无任何依赖）。`dist/` 下的两个页面都是自包含的单文件，
可直接双击打开或拷走。改了引擎或 `web/` 后重新 `npm run build`。

## 沙盘（index.html）

- **画笔**：数字 0–9（键盘 `0`–`9`）、墙（`W`）、源（`S`）。数字和墙可拖动连画。
  「源」以当前数字把格子标记为注入点，再点一次取消标记。
- **演化**：单步（空格）、播放/暂停（回车）、沉降到底。最近一步的主格为实线框，
  客格为虚线框，箭头旁的数字是搬运量。
- **平手策略**：scan / fifo / lifo，对应引擎的 `Strategy`。
- **源与稳态**：「注入一次」把各源设回源值；「求稳态」调用 `steadyState()`。
  勾选「对比锥面预测」后，每格右下角显示 `conePrediction()` 的值，不符的格标红。

## 对战草案（duel.html）

规则书里没有这部分，规则以 `duel.ts` 顶部的注释为准。

- 两方各有一层水，每层都是一块 `DiffusionBoard`，各自扩散、互不阻挡；同一格可同时有两方的水。
- 每回合固定 `perTurn` 个泉，位置自选：不能放在墙、已有的泉、或对方占领的格上。
  双方都放完后，所有泉把己方那一层重置为 9，然后沉降。
- 静止后逐格结算：一方水量 > 0 且不少于对方的 `ratio` 倍，这格归它；双方都不到倍数时维持原主，
  原本无主的继续无主（争夺中）。
- 一轮结束时占领过半者胜；否则打满回合数后比占领格数。
- 青方可选同屏玩家或电脑（`greedyMove`：逐个泉预演，选格数差最大的位置）。

草案 1（水带符号、相遇抵消、每手 1 泉）在提交 `9485c52` 里。

### 模拟结果（未定稿的参数）

`node sim.mjs quick` 在 7×7 下某一次运行的结果（先手胜 : 后手胜 : 平；样本小，只看趋势）：

| 设置 | 随机 vs 随机（60 局） | 贪心 vs 贪心（8 局） | 终局已占领 | 易主 次/局 |
| --- | --- | --- | --- | --- |
| 默认：2 泉、2 倍、原主保留、一起注入 | 31 : 26 : 3 | 3 : 4 : 1 | 82–87% | 0.7–2.6 |
| 不保留原主 | 23 : 27 : 10 | 0 : 0 : 8 | 0–12% | 0.6–1.8 |
| 1.5 倍 | 25 : 33 : 2 | 1 : 7 : 0 | 87–93% | 1.6–4.0 |
| 3 倍 | 31 : 27 : 2 | 0 : 5 : 3 | 64–74% | 0.1–0.3 |
| 每回合 1 泉 | 33 : 23 : 4 | 4 : 4 : 0 | 87–92% | 0.9–2.1 |
| 每回合 3 泉（6 轮） | 28 : 30 : 2 | 0 : 8 : 0 | 74–83% | 0.7–3.3 |
| 每回合后全部注入 | 58 : 1 : 1 | 8 : 0 : 0 | 93–94% | 0.8–2.9 |
| 每回合后只注入落子方 | 54 : 6 : 0 | 8 : 0 : 0 | 96–99% | 2.5–3.8 |

默认设置下贪心对随机为 8 : 0（先手）和 8 : 0（后手）。要点：不保留原主时盘面几乎全是无主；
另外两种注入时机先手两轮内获胜，所以界面只提供「一起注入」；易主很少，现规则偏向先到先得的圈地。

## 结构

- `build.mjs` 把擦除类型后的引擎与界面脚本拼进同一个 `<script type="module">`，
  所以 `web/app.js`、`web/duel.js` 直接使用引擎里的名字，不写 import。
